# ADR-0002 — Speech Transport Layer

**Status:** Accepted
**Date:** 2026-07-09
**Author:** Sentinel V2

---

## Context

MiniOmni2 communicates over a local HTTP server using a `multipart/x-mixed-replace` streaming response that interleaves raw audio bytes and text tokens. The naive implementation was to inline `httpx` requests directly inside `MiniOmni2Model`, binding the model driver to a specific wire protocol.

This means if MiniOmni2 is later served via WebSocket, gRPC, a local Python call, or a shared memory interface, the model class itself would need to change.

## Decision

All network I/O between a model driver and its runtime is mediated by a `ISpeechTransport` interface, defined in `conversation/transport.py`.

```python
class ISpeechTransport(abc.ABC):
    async def send_audio_request(
        self, url: str, payload: dict
    ) -> AsyncGenerator[Tuple[str, bytes | str], None]:
        ...
```

The concrete `HttpSpeechTransport` handles the `multipart/x-mixed-replace` parsing today. Model drivers receive a transport instance at construction:

```python
MiniOmni2Model(transport=HttpSpeechTransport())
```

## Motivation

- Decouples the wire protocol from the model logic.
- Allows testing model drivers with a mock transport without running a live server.
- Allows swapping transport (HTTP → gRPC → local process pipe) with zero changes to `MiniOmni2Model` or `ConversationEngine`.

## Consequences

- All model drivers that need network I/O must accept an `ISpeechTransport` in their constructor.
- `ISpeechTransport` implementations must not import from `conversation/session.py`, `api/`, or `runtime/`.
- Binary audio and text tokens must be yielded as `(event_type, content)` tuples so the engine can route them separately.

## Compliance Rule

> Transport depends on nothing above it. `ConversationEngine` depends on `ISpeechTransport`. No layer above `transport.py` may implement wire parsing inline.
