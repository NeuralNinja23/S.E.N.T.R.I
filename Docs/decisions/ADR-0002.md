# ADR-0002 — Decoupled Streaming Speech Pipeline

**Status:** Accepted (Supersedes original MiniOmni2 transport layer)
**Date:** 2026-07-09 (Updated: 2026-07-18)
**Author:** Sentri V2

---

## Context

Sentri V1 used MiniOmni2, a monolithic speech-to-speech model running as a Flask server on port `60808`. It communicated via `multipart/x-mixed-replace` HTTP streaming, interleaving raw audio bytes and text tokens in a single response. A dedicated `ISpeechTransport` / `HttpSpeechTransport` abstraction was created to decouple wire parsing from model logic.

This architecture was replaced entirely in V2. MiniOmni2 was decommissioned in favour of a **decoupled streaming speech pipeline** that composes independent, best-in-class providers for each stage of the voice turn.

## Decision

Voice turns are now processed by `ConversationRuntime` (alias `StreamingSpeechPipeline`), defined in `conversation/streaming_pipeline/pipeline.py`. It orchestrates four concurrent async workers connected by `asyncio.Queue` channels:

```
Audio Input
    ↓
┌───────────────────────┐
│  ASR Worker            │  Faster-Whisper (in-process, GPU)
│  (speech → transcript) │
└──────────┬────────────┘
           ↓
┌───────────────────────┐
│  LLM Worker            │  Ollama (Qwen3.5-4B-Uncensored, localhost:11434)
│  (transcript → tokens) │  with tool-calling loop (up to 5 turns)
└──────────┬────────────┘
           ↓
┌───────────────────────┐
│  Speech Planner        │  Sentence chunker with punctuation-aware splitting
│  (tokens → chunks)     │
└──────────┬────────────┘
           ↓
┌───────────────────────┐
│  TTS Worker            │  Kokoro ONNX (in-process, GPU)
│  (chunks → PCM audio)  │
└──────────┬────────────┘
           ↓
     Audio Output
```

The `ISpeechTransport` / `HttpSpeechTransport` abstraction is no longer in active use. Network I/O to Ollama is handled internally by `OllamaReasoningProvider` using a persistent `httpx.AsyncClient`.

## Motivation

- Each stage uses the best available model for its task rather than a single end-to-end model with compromises at every stage.
- Workers run concurrently: the TTS can synthesise the first sentence while the LLM is still generating the second, reducing perceived latency.
- Replacing any single provider (e.g. swapping Faster-Whisper for Moonshine ASR) requires writing one driver file and does not affect any other provider.
- The reasoning provider now supports a multi-turn tool-calling loop: if Ollama returns `tool_calls`, the provider executes them via `TOOL_REGISTRY`, feeds results back, and re-queries until a final text response is produced.

## Consequences

- All provider implementations live in `conversation/streaming_pipeline/providers/` and must conform to their respective interfaces (`ASRProvider`, `ReasoningProvider`, `TTSProvider`).
- Inter-worker communication uses typed `asyncio.Queue` channels, not direct function calls.
- The `ISpeechTransport` abstraction from V1 is retained in the codebase for reference but is no longer on the active code path.
- Binary audio and text tokens are yielded as `(event_type, content)` tuples, preserving compatibility with `ConversationEngine`'s routing logic.

## Compliance Rule

> Providers do not import each other. All data flows through `ConversationRuntime`'s queue channels. No provider may bypass the pipeline to communicate directly with another.
