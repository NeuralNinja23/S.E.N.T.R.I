# ADR-0003 — Inference Runtime Manager

**Status:** Accepted
**Date:** 2026-07-09
**Author:** Sentinel V2

---

## Context

MiniOmni2 runs as an independent Flask server on port `60808`. The initial implementation placed process-spawning logic inside the FastAPI lifespan (`main.py`) using hardcoded paths. Two problems arose:

1. **Wrong ownership**: Starting and stopping a model subprocess is runtime orchestration, not application startup logic. It does not belong in `main.py`.
2. **No state visibility**: The process was either running or not. There was no way for the UI, watchdog, or logging system to know whether the model was still loading, fully ready, crashed, or restarting.

## Decision

All process lifecycle management for inference backends is owned by `InferenceRuntimeManager`, defined in `runtime/model_runtime.py`.

`InferenceRuntimeManager` exposes:
- `state: InferenceRuntimeState` — observable state enum
- `start()` — spawn the process and wait for health probe success
- `stop()` — terminate gracefully
- `check_health()` — HTTP probe, not just port check

`InferenceRuntimeState` values:
```
STOPPED → STARTING → LOADING_MODEL → READY → BUSY → STOPPING → FAILED
```

`main.py` only calls `inference_runtime_manager.start()` and `.stop()`. It has no knowledge of paths, ports, or processes.

Configuration is read from `config.py`:
```python
MINIOMNI_HOME, MINIOMNI_SERVER, MINIOMNI_PORT, MINIOMNI_PYTHON
```

## Motivation

- Separates process orchestration from application startup logic.
- Exposes a state machine that the UI, watchdog, and logging can observe.
- Moves hardcoded paths into environment-configurable settings.
- Health probe (`GET /chat` → 405) validates model readiness, not just port availability (ports can be open while the model is still loading weights).

## Consequences

- `ConversationEngine` must never call `inference_runtime_manager`. It only calls the model client.
- `InferenceRuntimeManager` must never import from `conversation/session.py` or `api/`.
- Any future model (vision, embedding, reranker) that needs an independent process gets its own entry in `InferenceRuntimeManager`, not a new `main.py` block.

## Compliance Rule

> `InferenceRuntimeManager` knows how MiniOmni2 starts. `ConversationEngine` does not. These two must never be coupled.
