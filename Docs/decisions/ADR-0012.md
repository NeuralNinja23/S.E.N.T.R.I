# ADR-0012 — Task State Pausing and Telemetry Concurrency Safety

**Status:** Accepted
**Date:** 2026-07-19
**Author:** Sentri V2

---

## Context

In SENTRI's task management system:
- **Pending Task Leakage:** The tool execution manager could pause active worker loops, but tasks in `PENDING` state (queued but not yet active) would occasionally start executing anyway during a paused state. This led to state violations and unexpected tool executions.
- **Telemetry Race Conditions:** The API `/api/system-stats` polls network utilization statistics by reading global counters. Under high load or rapid client polling, multiple concurrent async requests accessed and updated the telemetry globals (`_last_net_io_time`, `_last_net_bytes_sent`, etc.) simultaneously, causing division-by-zero errors or incorrect calculations.

## Decision

We have resolved these concurrency and state issues through two targeted architectural choices:
1. **Pending Task Gates:** The worker loop and task managers check both the task's state and the global registry pause state before pulling any task from the queue or starting execution. Pausing now locks down both `RUNNING` and `PENDING` states.
2. **Telemetry Locking:** Access to network statistics globals in [system_stats.py](file:///c:/Users/JARVIS/Desktop/SENTRI/backend/app/api/system_stats.py) is guarded by a global `threading.Lock` (`_net_lock`). All calculations of bits-per-second values are executed inside a critical section.

## Motivation

- **Predictable Controls:** Pausing governance commands must guarantee that no new tasks start. Gating pending execution ensures total system silence.
- **Telemetry Thread Safety:** Fast concurrent UI queries or parallel browser tests could trigger race conditions. Synchronizing with a standard lock prevents mathematical corruption of global variables.

## Consequences

- Task execution latency when resuming is unaffected, as the registry check is a local boolean lookup.
- Fast parallel requests to `/api/system-stats` will serialize cleanly at the network telemetry calculation boundary.

## Compliance Rule

> Any shared telemetry globals must be accessed through a thread-safe synchronization lock, and all task worker loops must check pause state before transitioning pending tasks to active.
