# ADR-0010 — Centralized Response Cleaning

**Status:** Accepted
**Date:** 2026-07-19
**Author:** Sentri V2

---

## Context

During the Phase 3 implementation of SENTRI, response-cleaning logic (removing `<think>` tags, stripping conversational clichés, and deleting diagnostic prefixes) was implemented in an ad-hoc and duplicated fashion. The Ollama adapter, the voice streaming pipeline, and the API endpoints each had their own string-scrubbing routines.

This duplication led to:
- **Inconsistent Output:** Conversational clichés like "Ah," or "Very well, sir," were stripped in some paths but passed to the speaker in others.
- **Maintenance Overhead:** Changes to the cleaning logic (such as fixing think-tag patterns or adding new filtered clichés) required editing multiple source files.
- **Latency in Voice Mode:** Redundant string matching and regex searches on streaming chunks increased latency before sending audio to the client.

## Decision

We have centralized all text normalization and response cleaning into a single utility class: `ResponseCleaner`, located in [utils.py](file:///c:/Users/JARVIS/Desktop/SENTRI/backend/app/conversation/utils.py). 

All text generation and speech pipeline segments must route their outputs through this class before display or TTS synthesis.

The centralized `ResponseCleaner` handles:
1. Stripping reasoning markers (`<think>...</think>`).
2. Normalizing whitespace and line endings.
3. Filtering butler clichés and repetitive conversational tokens.
4. Stripping system or diagnostic tags (like ASR debug markers).

## Motivation

- **Single Source of Truth:** A single class controls what makes a response "clean," guaranteeing consistency between text and voice modes.
- **Performance:** Centralizing the regex patterns allows them to be pre-compiled at module load time, eliminating compilation overhead on active generation paths.
- **Testability:** The cleaning logic is decoupled from FastAPI and Ollama, allowing it to be unit-tested directly (see `TestBug11_CentralizedCleaner` in [test_all_bugs.py](file:///c:/Users/JARVIS/Desktop/SENTRI/backend/tests/test_all_bugs.py)).

## Consequences

- Direct string manipulation or ad-hoc regex scrubbing of generation outputs in `adapter.py` or `pipeline.py` is deprecated.
- Any future cliché or token that needs to be scrubbed must be added to the rules inside `ResponseCleaner`, not to individual modules.
- Both text and voice outputs are guaranteed to follow identical formatting and filtering rules.

## Compliance Rule

> All generated outputs must pass through the centralized `ResponseCleaner` in `app.conversation.utils` before being sent to the client or synthesized to audio.
