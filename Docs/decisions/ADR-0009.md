# ADR-0009 — Uncensored Model Policy

**Status:** Accepted
**Date:** 2026-07-18
**Author:** Sentri V2

---

## Context

Sentri is a personal AI companion running entirely on local hardware. It is not a public-facing product, a child-safe assistant, or a multi-tenant service. It serves a single owner (Nisarg) on a single machine.

Standard aligned models (Llama 3, Phi-4, Gemma, etc.) include refusal training that causes them to decline requests involving adult humour, edgy creative writing, security research discussions, or any topic the alignment team deemed sensitive. In a personal assistant context, these refusals are frustrating and counterproductive — the owner is asking their own machine a question and being told "I can't help with that."

The project evaluated several models before settling on the current choice. Models with heavy alignment (Phi-4 Mini, Llama 3.2) consistently produced refusals or empty responses on benign-but-edgy queries, triggering `Generation failure: empty response from model` errors in production.

## Decision

Sentri V2 uses **uncensored / unaligned models** as the default reasoning backend. The current model is:

```
hf.co/HauhauCS/Qwen3.5-4B-Uncensored-HauhauCS-Aggressive:Q4_K_M
```

**Guardrails are implemented at the system prompt level, not the model level.** Sentri's personality boundaries (defined in `app/Sentri/Instructions/sentri.md`) enforce:

- British butler persona and tone
- Refusal to assist with genuinely harmful actions (violence, illegal activity)
- Owner-awareness (Sentri knows who it serves and acts accordingly)

This means the model is *capable* of responding to any query, but *chooses* to stay in character based on its instructions — rather than being hard-blocked by alignment training it cannot override.

## Motivation

- **Zero false refusals**: The owner never encounters "I can't help with that" on legitimate requests.
- **Full creative range**: Jokes, stories, roleplay, and casual conversation work without awkward hedging or moralising preambles.
- **Prompt-level control is more flexible**: System prompt boundaries can be adjusted instantly without retraining or swapping models. Alignment training is baked in and cannot be tuned.
- **Local-only execution**: The model runs on local hardware, never touches the internet, and serves one person. The risk profile is fundamentally different from a public API.
- **Personality coherence**: Sentri's butler persona is defined by instructions, not by alignment artifacts. This produces more natural, consistent responses.

## Model Selection Criteria

When evaluating future uncensored models, prioritise:

1. **Parameter count**: 4B–8B range for real-time voice latency on consumer GPUs (RTX 3060 12GB).
2. **Quantisation**: Q4_K_M or Q5_K_M for optimal VRAM/quality balance.
3. **Tool calling support**: Must support Ollama's native tool calling format.
4. **No thinking loops**: Must not enter infinite `<think>` tag repetition. Set `think: False` in all payloads.
5. **Instruction following**: Must reliably follow system prompt persona instructions without drift.

## Consequences

- Sentri will comply with requests that aligned models would refuse. This is intentional and expected.
- Safety boundaries are entirely dependent on the system prompt. If `sentri.md` is deleted or emptied, there are no model-level guardrails. This is acceptable because the system is local and single-user.
- Model upgrades must be tested against the same criteria: no refusals on benign queries, reliable tool calling, stable persona adherence.
- This policy applies only to the local Sentri deployment. If Sentri is ever deployed as a service for multiple users, this ADR must be revisited.

## Compliance Rule

> Sentri uses uncensored models with prompt-level guardrails. Model-level alignment is not relied upon for personality or safety boundaries. Any model swap must be validated against the selection criteria above.
