# ADR-0001 — Conversation Engine Abstraction

**Status:** Accepted
**Date:** 2026-07-09 (Updated: 2026-07-18)
**Author:** Sentri V2

---

## Context

Sentri V1 used a cascaded pipeline: ASR → LLM → TTS. Each stage was implemented as a standalone service and called directly by the WebSocket handler. This created tight coupling between the transport layer, the speech model, and the frontend.

Replacing any one stage (e.g. switching Whisper for a better ASR) required touching the WebSocket handler, the service layer, and any test that referenced the old service.

## Decision

All communication between the API layer and any speech or reasoning model is routed exclusively through `ConversationEngine`.

The WebSocket handler (`api/websocket.py`) never imports a model implementation directly. It only calls:

```python
engine.run_voice_turn(audio_stream, history=history, websocket=websocket)
engine.run_text_turn(system_prompt, text_query, websocket=websocket)
engine.supports("streaming")
```

The `websocket` parameter is threaded through the call chain so that sub-components (e.g. the reasoning provider) can emit real-time status messages (tool call logs, progress indicators) directly to the connected client without coupling themselves to the WebSocket transport.

## Motivation

- Allows replacing the active speech pipeline (currently `ConversationRuntime` / `StreamingSpeechPipeline`) or reasoning model (currently Ollama + Qwen3.5-4B-Uncensored) without modifying the WebSocket handler, Memory layer, Runtime manager, UI, or Watchdog.
- Enforces a single entry point for all conversational interactions.
- Makes capability queries (`engine.supports("vision")`) the canonical way to branch on model features instead of `if model_name == ...`.
- The `websocket` passthrough enables tool-call logging without breaking the dependency rule (engine never depends on `websocket.py`; it receives the connection as a parameter).

## Consequences

- All speech models must implement `ISpeechToSpeechModel` from `conversation/interfaces.py`.
- All text reasoning paths must be exposed through `ConversationEngine.run_text_turn()`.
- No future code outside `conversation/` may import a model implementation class directly.
- `run_voice_turn` and `run_text_turn` accept an optional `websocket` parameter. Sub-components may use it for real-time logging, but must never assume it is present (it can be `None` in tests or headless runs).

## Compliance Rule

> The WebSocket handler depends on `ConversationEngine`. `ConversationEngine` never depends on `websocket.py`.
