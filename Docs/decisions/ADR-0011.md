# ADR-0011 — Deterministic Memory Deletion Interceptor

**Status:** Accepted
**Date:** 2026-07-19
**Author:** Sentri V2

---

## Context

Users occasionally request that the digital human forget specific facts or erase stored profile records (e.g., *"forget my favorite color"* or *"delete Rohan"*). 

Under the standard agent-tool pattern, the LLM is expected to parse the request, select the memory deletion tool, execute it, and return a confirmation. However:
- **LLM Refusal:** Uncensored or highly aligned models alike often trigger internal safety guidelines or refuse to execute deletion operations, answering instead with general refusals.
- **Stateless Refusals:** Because the model cannot change its own core memory without tool calling, it would frequently state it cannot modify past facts or claim the deletion is not possible.
- **Prompt Compliance:** The evaluation suite requires a specific confirmation phrasing upon memory erasure. Forcing the LLM to output this exact phrase reliably via prompts was fragile and prone to failure.

## Decision

We have implemented a **deterministic command interceptor** in the WebSocket handler ([websocket.py](file:///c:/Users/JARVIS/Desktop/SENTRI/backend/app/api/websocket.py)). 

When a text query matching memory deletion patterns is received:
1. The WebSocket interceptor matches the deletion command.
2. The SQLite database is directly queried, and matching records are deleted immediately via the `MemoryRuntime` backend.
3. The server immediately returns a clean, structured confirmation to the client: *"I have removed that information from this conversation..."*
4. The request bypasses the LLM reasoning pipeline entirely, preventing any refusals or formatting errors.

## Motivation

- **100% Deletion Success:** Directly executing the SQL query guarantees that the fact is removed from `sentri_memory.db` without relying on LLM tool choice.
- **Reliable UI/Voice Feedback:** By returning a hardcoded, clean confirmation, the system complies with testing specifications and avoids verbose or defensive LLM dialog.
- **VRAM and Compute Savings:** Deletions execute in sub-milliseconds, saving GPU cycles and avoiding Ollama inference latency.

## Consequences

- Direct deletions do not pass through the intent classification or retrieval planning stages.
- The conversational context for the rest of the session is updated immediately, ensuring subsequent turns do not retrieve the deleted fact.
- Future memory categories or keys must be updated in the interceptor rules to remain supported.

## Compliance Rule

> Requests to forget, erase, or delete stored user profile facts must be intercepted at the API gateway level and executed deterministically against the memory store, bypassing LLM generation.
