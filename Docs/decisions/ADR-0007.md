# ADR-0007 — Provider Independence

**Status:** Accepted
**Date:** 2026-07-15 (Updated: 2026-07-18)
**Author:** Sentri V2

---

## Context

Sentri V2 implements a modular, decoupled speech pipeline composed of ASR (Faster-Whisper), Reasoning (Ollama + Qwen3.5-4B-Uncensored), Speech Planner (sentence chunker), and TTS (Kokoro ONNX) components. As the project expands, maintaining strict separation of concerns is vital to ensure that providers remain interchangeable and easily testable.

## Decision

We enforce a strict rule of **Provider Independence**:
* **No provider implementation may import, depend on, or communicate directly with another provider.**
* All communication and data passing must be orchestrated exclusively by `ConversationRuntime` (the `StreamingSpeechPipeline`).
* All exchanges between components must pass through the strongly typed, formal schemas defined in `contracts.py`.

### Tool Calling and Provider Independence

The reasoning provider (`OllamaReasoningProvider`) now supports a multi-turn tool-calling loop. When the model requests a tool call, the provider executes it via `TOOL_REGISTRY` and feeds the result back to Ollama. This does **not** violate provider independence because:

- Tool execution is self-contained within the reasoning provider's own `stream()` method.
- The tool registry (`app/tasks/task_registry.py`) is a flat function map, not another provider.
- No other provider (ASR, TTS, Speech Planner) is imported, referenced, or affected.
- The optional `websocket` parameter is received from the pipeline, not imported.

## Consequences

* **Extreme Interchangeability**: Replacing an ASR engine (e.g., swapping Faster-Whisper for Moonshine) requires writing a single provider driver and does not affect the Reasoning or TTS codebases.
* **Ease of Testing**: Providers can be unit-tested in isolation by feeding them mock contract payloads.
* **Architectural Cleanliness**: Prevents spaghetti-like coupling between disparate cognitive domains.
* **Tool Awareness is Reasoning-Only**: Only the reasoning provider interacts with tools. ASR and TTS providers remain pure signal processors with no awareness of tool calling.

## Compliance Rule

> Providers do not import each other. All data flows through `ConversationRuntime`'s queue channels. Tool execution is encapsulated within the reasoning provider and does not leak into other providers.
